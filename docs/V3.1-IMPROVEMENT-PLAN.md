> **기준:** `v3.0` @ `4ff92a1` · 참조 `v2.1-PRODUCTION-MODE` (읽기 전용)

## 1. 문제 정의

Agent-K v3.0은 기능적으로 넓다 — Phase 10, Feature ID 338개, 동작하는 에이전트 루프, PlanCard, 서브에이전트, 워크트리, MCP. 그러나 **완성된 제품처럼 느껴지지 않는다.** 불만은 두 축이다.

**UI:** 패널이 내부 개발 도구처럼 읽힌다 — 첫 실행이 빈 화면, 라이트 테마 깨짐, 포커스 표시 없음, 토큰 시스템 2개, 타임라인 chrome 중복, 아이콘/메뉴 불일치, 디버그 chrome이 모든 사용자에게 노출.

**에이전트:** 모든 메시지를 코딩 작업으로 취급한다 — "hi"에도 코드베이스 prefetch + verification-first 분석이 돌고, v2.1의 풍부한 모드 프롬프트는 버려지며, 툴 결과는 전송 간 유실되고, compaction은 사용자 지시를 지운다. **작은 대화에는 과잉, 실제 후속 작업에는 정보 부족.**

두 축은 개별 버그가 아니라 두 개의 시스템 갭이다: **(1) 사용자 메시지와 무거운 컨텍스트/하네스 파이프라인 사이의 의도(intent) 레이어 부재**, **(2) 프롬프트·토큰·타임라인 chrome의 단일 소스 부재**. Agent Loop v2가 첫 번째를 Intent Gate + 명시적 PLAN→EXECUTE→VERIFY→FIX 사이클로 해결하고, UI 감사가 두 번째를 토큰 통합·테마 정합·컴포넌트 중복 제거로 해결한다.

### 2.3 "hi" 버그 근본 원인 (확정)

사용자가 "hi"라고 인사했는데 에이전트가 코드 분석을 시작한 사슬:

1. `chatSend.ts:1461-1472` — PrefetchEngine이 **매 전송 무조건** 실행. "hi" → `inferTaskType` = `general` → `active_file`/`diagnostics`/`git_diff`/`open_tabs`를 user 프롬프트에 주입.
2. `VerificationFirstPrompt.ts:9` — "gather → act → verify each turn. Do not stop with a final answer until verification passes." Agent 모드에 무조건 주입.
3. `ModeRegistry.ts:212-233` — `classifyAutoMode`에 대화/인사 클래스가 없고 agent로 기본. 의도 게이트 자체가 없음.
4. ISSUE-01 — v2.1의 풍부한 프롬프트(오프닝 리드, ask_question 규율 등)는 chat-ui에 있고 버려짐.

## 3. 설계 방향

### 3.1 UI 원칙 — v3.1이 느껴져야 하는 것

1. **Calm by default** — 디버그 chrome 없음, 동시 애니메이션 ≤2, 모션 과부하 없음.
2. **First-run friendly** — 빈 패널 금지. 환영 + 시작 액션 3개 + provider 설정 힌트.
3. **One system** — 토큰 소스 1개, 아이콘 시스템 1개(SVG), 타임라인 카드 시스템 1개, settings 저장 모델 1개.
4. **Theme-correct** — 두 테마 모두 토큰 파생; 하드코딩 색상 0; WCAG AA 대비.
5. **Responsive** — 280px 패널 폭에서 사용 가능; 주요 컨트롤의 아이콘-only 축소 금지.

### 3.2 에이전트 원칙 — v3.1이 느껴져야 하는 것

1. **Intent-aware** — 무거운 파이프라인 **이전에** conversational / question / task 분류; prefetch·verify-first·harness·툴 가용성 게이트.
2. **Verify-before-answer** — task 턴은 PLAN → EXECUTE → VERIFY → FIX (프롬프트+게이트 강제, FSM 아님); 근거 없는 완료 선언 금지.
3. **Self-critical** — 편집 후 inline critique (최대 2회); 에러는 데이터이지 런 킬러가 아님.
4. **Context-continuous** — 툴 결과가 전송 간 생존; compaction이 사용자 지시 보존; prefetch 소유자 1개.
5. **Local-model friendly** — parser fallback, tier 적합 툴, CJK 인식 토큰 예산.

## 4. 시스템 설계

### 4.1 아키텍처 원칙

1. **Ports & adapters** — core는 인터페이스+순수 로직, host는 `vscode`/fs 어댑터. 기존 `AgentLoopDeps`(`AgentLoopController.ts:105-110`) 주입 패턴을 모든 신규 기능이 따른다.
2. **Pure core, IO at edges** — core에 `vscode`/React/network 금지. `node:fs`는 명시적 IO 모듈만(`PrefetchEngine.ts`). `shared`는 타입만.
3. **단일 책임 per file** — 소프트 캡 **300~400줄**, 하드 캡 **500**. 줄 수가 아니라 책임으로 분리.
4. **Constructor DI** — core에 모듈 싱글턴 금지. host는 싱글턴 허용(`runtimeSingletons.ts`).
5. **Registries over switches** — 확장은 엔트리 추가로: `ToolRegistry`, `modeRegistry`, `RoutingHeuristics.SIGNAL_PRIORITY`, `CONTEXT_STRATEGIES`.
6. **Strategy interfaces for policies** — `IntentClassifier`, `PhasePolicy`, `RetryPolicy`, `SelfCritiquePolicy`, `CompactionStrategy`, `ToolResultFormatter`: 정책당 인터페이스 1개 + 기본 구현 + 레지스트리.
7. **Events are observation** — `AgentLoopEvent` 유니온 확장으로 관찰; 루프 제어 흐름은 불변.
8. **Type-only shared** — 신규 프로토콜 타입(`IntentKind`, phase/prefetch 이벤트)은 `shared/src/common|protocol`.
9. **Naming** — 클래스 `XxxClassifier|Policy|Tracker|Store|Runner|Formatter|Emitter`; 순수 함수 `verbNoun`; 클래스 모듈 PascalCase, 함수 모듈 camelCase.
10. **Testability by construction** — 순수 모듈은 colocated `*.test.ts`; host 배선은 fake deps; UI는 jsdom 렌더 테스트.

**의존성 방향 (비순환):**
```
shared (types) ──► core ──► host ──► extensions/agent-k
      └────────► tools/providers ──► host
chat-ui ──► shared/protocol only   (알려진 예외: 4개 파일이 @agent-k/plan import — 확장 금지)
```

### 4.2 컴포넌트 분해

#### 4.2.1 Intent Gate — `core/src/intent/` (타입은 `shared`)

```ts
// packages/shared/src/common/intent.ts (types only)
export type IntentKind = 'conversation' | 'question' | 'task';
export interface IntentGates {
  prefetch: boolean;
  verificationFirst: boolean;
  harnessBlocks: boolean;
  toolSchemas: 'full' | 'readonly' | 'none';
}
export interface IntentVerdict {
  kind: IntentKind; confidence: number; reason: string; gates: IntentGates;
}

// packages/core/src/intent/IntentClassifier.ts
export interface IntentClassifierInput {
  userText: string; mode: AgentMode;
  hasImages?: boolean; hasInlineEdit?: boolean; priorTurns?: number;
}
export interface IntentClassifier {
  readonly id: string;
  classify(input: IntentClassifierInput): IntentVerdict | Promise<IntentVerdict>;
}

// packages/core/src/intent/IntentRule.ts
export interface IntentRule {
  id: string; priority: number;
  match(input: IntentClassifierInput): IntentVerdict | null;
}

// packages/core/src/intent/HeuristicIntentClassifier.ts
export class HeuristicIntentClassifier implements IntentClassifier {
  readonly id = 'heuristic-v1';
  constructor(private readonly rules: IntentRule[] = DEFAULT_INTENT_RULES) {}
  classify(input: IntentClassifierInput): IntentVerdict;
}

// packages/core/src/intent/ModelIntentClassifier.ts (선택, 기본 off)
export class ModelIntentClassifier implements IntentClassifier {
  readonly id = 'model-v1';
  constructor(private readonly runModel: RunModelFn,
              private readonly fallback: IntentClassifier) {}
  async classify(input: IntentClassifierInput): Promise<IntentVerdict>;
}

// packages/core/src/intent/IntentGate.ts
export class IntentGate {
  constructor(private readonly classifier: IntentClassifier) {}
  async evaluate(input: IntentClassifierInput): Promise<IntentVerdict>;
  apply(verdict: IntentVerdict, base: IntentGateTargets): IntentGateTargets;

```

- **Host 소비:** `chatSendConfig.ts`가 게이트 평가 → `verdict.gates`를 `AgentLoopConfig`와 `registry.getSchemas(mode, { ...schemaOpts, intentKind })`에 전달.
- **Tools 소비:** `GetSchemasOptions`(`tools/src/types.ts:140-147`)에 `intentKind?: IntentKind`; `question`/`conversation`이면 write 툴 숨김.
- **Loop 소비:** `AgentLoopConfig`에 `intentKind?`; `ContextAssembler`가 `harnessBlocks === false`면 verify-first/harness 주입 스킵.
- **근거:** 휴리스틱 우선(결정적·테스트 가능·지연 0). 모델 분류기는 전략 교체. 기본 verdict는 `task`(현행 동작)라 게이트는 활성화 전까지 inert.

#### 4.2.2 Explicit cycle — `core/src/loop/phases/`

```ts
export type LoopPhase = 'plan' | 'execute' | 'verify' | 'fix' | 'done';
export interface PhaseTransition { from: LoopPhase; to: LoopPhase; turn: number; reason: string; }
export interface PhaseObservation {
  turn: number; hasToolCalls: boolean; toolNames: string[];
  toolOk: boolean; editedPaths: string[]; verifyPending: boolean; finalProse?: string;
}
export interface PhasePolicy { next(current: LoopPhase, obs: PhaseObservation): LoopPhase; }
export class DefaultPhasePolicy implements PhasePolicy { /* plan→execute→verify→fix→done */ }

export class LoopPhaseTracker {
  constructor(private readonly policy: PhasePolicy = new DefaultPhasePolicy()) {}
  current(): LoopPhase;
  observe(obs: PhaseObservation): PhaseTransition | null;
  reset(): void;
}
export class PhaseEmitter {
  constructor(private readonly tracker: LoopPhaseTracker,
              private readonly emit: (e: AgentLoopEvent) => void) {}
  observe(obs: PhaseObservation): void;   // 전이 시 { type:'phase', ... } emit
}
```

- `AgentLoopEvent`에 `| { type: 'phase'; phase: LoopPhase; turn: number; reason: string }` 추가.
- 컨트롤러는 정확히 두 지점에서 `phaseEmitter.observe()` 호출: 모델 턴 후, 툴 배치 후. FSM·하드 전이 없음.
- **프롬프트 강제:** `PhasePromptInjector`(harness/)가 `PromptInjector` 체인으로 짧은 phase 지시 주입. **게이트 강제:** `PhasePolicy`는 `verifyPending === false`일 때만 `done`; `VerifyExitCheck` 확장.
- **기각 대안:** full FSM — AGENTS.md가 일상 AgentLoop에 Plan FSM 확장 금지.
